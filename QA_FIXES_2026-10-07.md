## 🚨 Deploy checklist (order matters)

1. **IAM role for the login function** — Google Cloud console → IAM → the service account the functions run as (usually `<project-number>-compute@developer.gserviceaccount.com`) → add role **Service Account Token Creator**. Without it `adminLogin` can't create the sign-in token.
2. **Enable Firebase Authentication** (Firebase console → Authentication → Get started). No sign-in provider needs to be switched on — custom tokens work without one.
3. **Deploy the Cloud Functions** from `website_app` (`functions/` and `deafult/` hold the same code — deploy one codebase, e.g. `firebase deploy --only functions:deafult`). New: `adminLogin`, `adminRequestPasswordReset`, `adminResetPassword`. Changed: `sendOTP`. Check the Twilio secrets are set (`TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_VERIFY_SERVICE_SID`) and `SENDGRID_API_KEY` (used for the reset e-mail).
4. **Rotate the admin password** — the old build shipped `admin@bayanatz.com` / its default password inside `main.dart.js`, so treat it as public:
   ```
   cd website_app/functions
   gcloud auth application-default login
   node scripts/set_admin_password.js admin@bayanatz.com 'A-New-Strong-Pass1' "Bayanatz Admin" super_admin
   ```
5. **Build + deploy the admin app**, then **open Job Listing once** while signed in: it writes the new `Public_Listed` flag on every existing job (the public site only lists jobs that have it).
6. **Deploy the rules** from `web_app_admin`: `firebase deploy --only firestore:rules,storage`.
   Do this **after** steps 3–5 — the new rules need the new login, and the public site needs `Public_Listed`.
7. **Build + deploy the public site.**

## Behaviour changes to know about
- Admin login needs the deployed `adminLogin` function (+ IAM role). Old sessions in localStorage are ignored — everyone signs in once more.
- Visitors can no longer read draft / inactive / removed jobs, even by link. Jobs saved before this build are hidden from the site until the admin opens Job Listing once (step 5).
- One application per e-mail per job.
- Applicant CVs are only downloadable through the admin (stored download URLs still work for the admin).
- Tablets show the admin at a slightly smaller scale instead of cutting it.
