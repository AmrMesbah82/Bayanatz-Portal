# Bayanatz Jobs Admin — QA bug fixes (27 Sep 2026)

Source: *Bayanatz_Jobs_Admin_QA_Bug_Report.pdf* (36 bugs, BUG-05 → BUG-50).
Every code change carries a `// BUG-xx` comment, so `grep -rn "BUG-" lib` finds each fix.

> ⚠️ Written without a Flutter SDK (none was reachable from the edit environment).
> Run `flutter pub get && flutter analyze`, then walk the test list at the bottom before deploying.

---

## High

### BUG-05 — Refresh / Back button don't work (URL never changes) · *All pages*
**Cause:** the top navbar switched sections with `Navigator.pushReplacement(MaterialPageRoute(...))`, so the address bar stayed on `/`. F5 always went Home and Back left the app.
**Fix:** every section now has a go_router URL, and the navbar uses `context.go()`:
`/` Home · `/jobs` Job Listing · `/applications` · `/inquiries` · `/admin/dashboard` Web Page · `/admin/services` Services (it had no route).
`GoRouter.optionURLReflectsImperativeAPIs = true` in `main.dart` so pages opened with `context.push()` (e.g. About Company) also update the URL.
**Files:** `core/main_widgets/app_admin_navbar.dart`, `core/router/app_router.dart`, `core/main_widgets/admin_sub_navbar.dart`, `main.dart`

### BUG-08 — First "Required Skill" is never saved · *Post / Edit Job*
**Cause:** the first skill row was built with `TextEditingController()` created **inside `build()`** — a throw-away controller nobody read (and reset on every rebuild). Only the rows added with "+ Skill" were in `_skills`.
**Fix:** the first row is now a real entry of `_skills` (the list always has at least one row, and that row carries the "Required Skills" label). Completely empty rows are skipped on save; a half-filled row (only EN or only AR) is flagged.
**Files:** `job/.../job_listing_edit.dart`, `widgets/job_listing_edit/edit_sections.dart`

### BUG-09 — Job Preview shows dummy data · *Post Job → Preview*
**Cause:** for a new job the preview looked the job up by id `'new'`, found nothing, used `JobPostModel.empty()` and filled blanks with hard-coded "UI and UX Designer" / "3 Weeks".
**Fix:** the edit page passes the form's current model (`draft: _buildModel()`) to the preview; placeholders removed (`-` when a value is really empty); duration and salary show real values + currency; title typo "Journy" fixed ("Preview Job Post Details"); a duplicated "Employment Type" label corrected to "Employment Duration".
**Files:** `job_listing_preview.dart`, `edit_form_helpers.dart`

### BUG-10 — "Save For Later" on an empty form → "Untitled" job with invented values, then white screen
**Causes:** (1) no validation for drafts; (2) unpicked dropdowns were written with enum defaults (On Site / Junior / Full Time) and the card had a hard-coded **"Egypt"**; (3) white screen: the Job Listing page's listener popped **whatever route was on top** on every save, and the edit flow could end up popping twice.
**Fix:** a draft now needs at least a job title (message + scroll to the field); a new `unsetFields` list on the job remembers which dropdowns were never picked, so cards/preview/details show nothing instead of fake values, and the edit form re-opens them empty; the edit page now closes **itself** after a successful save (only if it's the top route) and the list page only refreshes.
**Files:** `job_listing_model.dart`, `job_listing_edit.dart`, `job_listing_main.dart`, `job_card.dart`, `job_details_tab.dart`, `job_listing_preview.dart`

### BUG-11 — Scheduled / Ended never happen
**Cause:** nothing ever changed the stored status after publishing.
**Fix:** status is derived from the hiring dates whenever a job is read or saved (`JobPostModel.deriveStatus` / `withDerivedStatus`): today before start → **Scheduled**, after end-of-day of the end date → **Ended**, otherwise Active. Only the "live" statuses are derived (Inactive / Draft / Removed are left alone). Tabs, cards and the dashboard's "Recruitment End" pick this up automatically.
*Optional:* a daily Cloud Function writing the same rule back to Firestore would keep the public site in sync too.
**Files:** `job_listing_model.dart`, `job_listing_cubit.dart`, `job_card.dart`

### BUG-12 — Turning "Job Status" off doesn't enable Save
**Cause:** the Save button is gated by the app-wide `FormDirtyScope`, which only notices typing in text fields and dropdown picks — not the `FlutterSwitch` (or dates).
**Fix:** the job edit page opts out (`requireChanges: false`) because it already has its own exact change check (`_hasChanges`), which includes the switch and the dates.
**Files:** `edit_form_helpers.dart`

## Medium

### BUG-19 — Raw database id as a job name · *Home – Jobs Performance*
**Fix:** titles come from the job (`displayTitle`), falling back to "Untitled job" — never the Firestore id. Drafts can no longer be saved without a title (BUG-10).
**Files:** `careers_model.dart`, `job_listing_model.dart`

### BUG-20 — Test/junk data on the live dashboard
**Code side:** removed jobs are excluded from every dashboard widget, the Job Posting chart no longer lists departments (BUG-21), and removed jobs can now be **deleted permanently** (BUG-45).
**Still needed (data, not code):** delete the junk jobs / departments / applications ("asdasd", "Qqqqq", "Cxvxcv"…) from the production Firestore, or point the live site at a separate test project.

### BUG-21 — "Job Posting Status" chart shows departments
**Fix:** one bar per status (Active / Closed / Scheduled / Draft), each coloured like its legend; the y-axis auto-scales (max 1 → axis 0–1 instead of 0–10).
**Files:** `careers_model.dart`, `careers_charts.dart`

### BUG-22 — KPI totals contradict each other
**Causes:** Hybrid jobs were counted nowhere; one failing Firestore read (e.g. applications) threw the whole dashboard into an all-zero fallback, so some loads showed zeros.
**Fix:** all widgets come from one filtered job list; "Office Jobs" = On Site + Hybrid; Job Status donut and Job Posting chart use the same buckets; each data source now loads independently (one failure no longer zeroes everything). "Active Job" → "Active Jobs".
**Files:** `careers_model.dart`, `careers_cubit.dart`

### BUG-23 — Web Page "Preview Screen" body is blank
**Fix (partial):** the page passed `'web page'` (lower-case) to the navbar, so "Web Page" wasn't highlighted — fixed. The preview body is unchanged (still the site shell only); rendering the website's Home page inside the admin was removed at the owner's request.
**Files:** `main_preview.dart`, `app_admin_navbar.dart`

### BUG-24 — Inquiries: empty table/charts give no feedback; uneven columns
**Fix:** "No inquiries yet" row under the header; "No data yet" in empty Entity Types / Entity Size / Location charts (the size bar no longer draws 5 fake coloured parts); columns size to their content between a min and a max width.
**Files:** `inquiry_main.dart`

### BUG-25 — Web Page CMS: logo empty and "Last Updated On —"
**Cause of the date:** Firestore `Timestamp` was detected with `value.runtimeType.toString().contains('Timestamp')` — **type names are minified in release web builds**, so it never matched in production. Same bug existed in the Home and Services models.
**Fix:** duck-type the Timestamp (`(value as dynamic).toDate()`). Logo: when no custom logo is uploaded the field now shows the bundled default logo (which is what the live header shows) with a note.
**Files:** `main_model.dart`, `home_model.dart`, `services_model.dart`, `services_repo_impl.dart`, `main_main.dart`

### BUG-26 — Wrong menu item highlighted on sub-pages
**Fix:** About Company highlights **Job Listing** and has a "← Job Listing" breadcrumb (new reusable `AdminBackLink`). Create Department also highlighted "Home" → fixed (BUG-46).
**Files:** `about_us_company_main.dart`, `core/main_widgets/admin_back_link.dart`, `department_create.dart`

### BUG-27 — Publish/Save fails silently
**Fix:** a failed Publish shows a message ("Please complete the highlighted fields" or the specific rule), opens the section and scrolls to the first section with a problem. Required text fields now also show **"This field is required."** under the field (app-wide change in `CustomTextField`).
**Files:** `job_listing_edit.dart`, `core/custom/2-custom_textfield.dart`

### BUG-28 — No validation on salary, max applications, dates
**Fix:** Max salary ≥ Min salary; Max applications ≥ 1; start date not in the past; end date after start and not in the past (unchanged dates on existing jobs aren't re-checked, so an ended job can still be edited); errors shown under the fields. Date pickers use the admin red instead of the theme yellow and block past days.
**Files:** `job_listing_edit.dart`, `edit_form_helpers.dart`, `edit_sections.dart`, `core/custom/4-custom_dropdwon_calander.dart`, `core/widget/date_pic.dart`

### BUG-29 — Hiring dates can't be changed after creation
**Fix:** the **end date is always editable** (extend/shorten a deadline, with validation). The start date is locked only once hiring has actually started. An Ended job's switch shows as on, so extending the end date re-opens it.
**Files:** `job_listing_edit.dart`, `edit_form_helpers.dart`

### BUG-30 — Deleting a department that still has jobs
**Fix:** deletion is blocked with "This department has N jobs. Move them … first." Renaming a department now also moves its jobs to the new name (jobs store the name, so a rename used to orphan them). The department list page no longer pops an extra page after edit/delete.
**Files:** `department_edit.dart`, `department_main.dart`

### BUG-31 — Dashboard numbers wrong after adding jobs
**Causes:** dashboard computed once at app start; Hybrid not counted; donut percentages based on the number of departments; "Employment Types" read applicants' experience level; zero score distribution drawn as a full bar.
**Fix:** Home recomputes the dashboard every time it opens; percentages = part/total; "Total Jobs" in the donut centre; Employment Types = jobs' Full Time / Part Time (+ Unspecified); empty states instead of fake "No Data = 1" slices; zero score bar = grey track; removed jobs/departments excluded.
**Files:** `careers_main.dart`, `careers_model.dart`, `careers_charts.dart`, `segmented_score_bar_widget.dart`, `careers_cubit.dart`

### BUG-32 — Export does nothing (Applications) / Download does nothing (Inquiries)
**Cause:** Applications' Export had `function: () {}`. Inquiries showed its errors ("enter a file name", "no inquiries") in a SnackBar **behind the dialog's barrier**, so it looked dead.
**Fix:** new shared `csv_export_dialog.dart`: validates the file name inside the dialog, always downloads (header-only when empty, with a note), confirms the download, UTF-8 BOM so Excel shows Arabic. Used by both pages.
**Files:** `core/main_widgets/csv_export_dialog.dart`, `application_main.dart`, `inquiry_main.dart`

### BUG-34 — Arabic job text and Max Applications missing on Job Details
**Fix:** Arabic About / Requirements / Preferred Skills are shown under the English ones, skills show both languages; `maxApplications` is parsed tolerantly (num or string). Default documents are prefilled in Arabic ("السيرة الذاتية", "خطاب التغطية").
**Files:** `job_details_tab.dart`, `job_listing_model.dart`, `job_listing_edit.dart`

### BUG-35 — Applications: removed jobs listed, Time Frame dead, Filter opens "Sort"
**Fix:** removed and draft jobs are no longer job tabs; Time Frame opens a date-range picker (with a clear ✕) and filters by application date; the dialog is titled "Filter", uses the admin red and has a close button.
**Files:** `application_main.dart`, `core/main_widgets/application_filter_dialog.dart`

### BUG-36 — Inquiries filters "No options" and dropdowns never close
**Fix:** Status lists New / Replied / Closed and Entity Type lists the form's fixed types, even with no data; "Calendar" is a real date-range filter; the shared dropdown now allows **one open menu at a time**, closes on any outside click (raw pointer-down instead of a gesture that lost the tap arena) and on **Escape**.
**Files:** `inquiry_state.dart`, `inquiry_cubit.dart`, `inquiry_main.dart`, `core/custom/1-custom_dropdwon.dart`

## Behaviour changes to be aware of
- Removed jobs are excluded from all dashboard numbers.
- "Office Jobs" now includes Hybrid.
- Required text fields show "This field is required." under the field everywhere (was a red border only).
- New job documents store an `unsetFields` key (`Unset_Fields` in Firestore). The public site ignores it.
- Status "Scheduled"/"Ended" is computed on read; the stored value is updated the next time the job is saved.
