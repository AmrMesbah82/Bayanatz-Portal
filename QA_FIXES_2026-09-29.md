## 🚨 Deploy checklist (order matters)

1. **Create the admin account(s)** — Firebase console → Authentication → enable *Email/Password* → add user.
   Then Firestore → create a document **`admins/<that user's UID>`** (any field, e.g. `email`). Without it the new login says "No admin access".
2. **Twilio secrets + rotate the key** (BUG-51). The old Auth Token was public inside `main.dart.js` → **rotate it in the Twilio console first**, then:
   ```
   firebase functions:secrets:set TWILIO_ACCOUNT_SID
   firebase functions:secrets:set TWILIO_AUTH_TOKEN
   firebase functions:secrets:set TWILIO_VERIFY_SERVICE_SID
   ```
3. **Deploy Cloud Functions** from `website_app` (`functions/` and `deafult/` hold the *same* code; they export the same function names, so deploy only one codebase, e.g. `firebase deploy --only functions:deafult`). New function: `submitContactForm`. `sendContactEmail` / `sendContactConfirmation` are no longer exported (they were an open mail relay) — delete them in the console if they stay listed.
4. **Deploy the security rules** from `web_app_admin`: `firebase deploy --only firestore:rules,storage` (new files `firestore.rules`, `storage.rules`, wired in `firebase.json`).
5. **Storage CORS** (BUG-77, BUG-18): `gsutil cors set cors.json gs://web-app-admin-33b9a.firebasestorage.app`
6. Build + deploy **both** sites (`flutter build web` in each project, then hosting).

## Behaviour changes to know about
- **Login required** for the admin (BUG-01). No admin document → "No admin access".
- Contact submissions are created **only** by the `submitContactForm` function. An old site build that writes directly will be refused by the new rules → deploy site + functions + rules together.
- On phones and portrait tablets the admin keeps its full desktop layout with horizontal scrolling instead of a squeezed layout.
- Confirm dialogs show **Cancel + Confirm** everywhere.
- Footer on the public site scrolls with the page.
- Jobs: public read is still open for all jobs (drafts included) so the site's client-side filter keeps working; tighten later if needed.
- Our Teams preview still shows the saved version (not unsaved edits).
